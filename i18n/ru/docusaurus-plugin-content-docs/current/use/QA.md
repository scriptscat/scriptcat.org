## Режим разработчика / разрешения для пользовательских скриптов

#### В: ScriptCat показывает «Режим разработчика не включён», скрипты не работают?

Начиная с Chrome 120+ и новых версий Edge браузеры требуют вручную включить разрешения для запуска скриптов. См. [Включение поддержки пользовательских скриптов](/docs/use/open-dev/).

Если разрешение уже включено, а предупреждение остаётся — перезапустите браузер или перезагрузите расширение.

## Скрипты не работают

#### В: Установил(а) скрипт, но эффекта нет?

1. **Не включено «Allow User Scripts»** — см. [Включение поддержки пользовательских скриптов](/docs/use/open-dev/)
2. **Холодный старт** — сразу после открытия браузера скрипты могут ещё не загрузиться. Обновите страницу
3. **Конфликт расширений** — блокировщики рекламы (например, uBlock Origin) могут вызывать ошибки скриптов

#### В: Скрипт работает в Tampermonkey, но не в ScriptCat?

Реализации API ScriptCat и Tampermonkey немного отличаются. Обновитесь до последней версии. Если проблема остаётся — создайте Issue на [GitHub](https://github.com/scriptscat/scriptcat/issues).

## Ограничения CSP / Trusted Types {#csp-trusted-types}

#### Q: Что делать, если CSP сайта мешает работе скрипта?

В разделе ScriptCat **Network Rules** («Сетевые правила») выберите **Инструменты → Сетевые правила → Новое правило → Удалить CSP**. В поле **Сайты** укажите только сайт, на котором возникла проблема, например `example.com`. Сохраните правило и обновите уже открытые страницы.

Шаблон **Remove CSP** удаляет CSP-заголовки ответа для документов в основном и вложенных фреймах. При желании можно также удалить `X-Frame-Options`.

#### Q: Что делать при ошибке `This document requires 'TrustedHTML' assignment.`?

Обычно это означает, что браузер отклонил операцию с DOM из-за политики Trusted Types на сайте. Сайт может включить Trusted Types директивой CSP `require-trusted-types-for 'script'`; такая ошибка может возникнуть, если userscript выполняет запрещённую политикой операцию. Браузер применяет политику безопасности сайта, поэтому одно это сообщение не доказывает, что проблема вызвана ScriptCat.

Если ограничение задаётся принудительно через CSP-заголовок ответа документа, может помочь правило **Remove CSP** только для этого сайта. Оно не обязательно устранит ошибку, если её причина — не удаляемый CSP-заголовок ответа.

#### Q: Почему ScriptCat не удаляет CSP для всех сайтов по умолчанию?

CSP и Trusted Types помогают снизить риски, например межсайтового выполнения скриптов (XSS). Удаление CSP ослабляет встроенную защиту подходящего сайта. Создавайте правило только для сайтов, где оно действительно необходимо. Область **Все сайты** доступна, но перед сохранением ScriptCat запрашивает подтверждение.

:::warning Предупреждение о безопасности

Не выбирайте область **Все сайты**, если вы не понимаете и не принимаете связанные с этим риски.

:::

:::info О проблеме совместимости Trusted Types в ScriptCat

[ScriptCat #1239](https://github.com/scriptscat/scriptcat/issues/1239) также содержал отдельную проблему совместимости `GM_xmlhttpRequest`; она исправлена в [ScriptCat #1242](https://github.com/scriptscat/scriptcat/pull/1242). Это исправление не отключает и не обходит Trusted Types и не изменяет CSP сайта. Если у вас старая версия ScriptCat, обновите её.

:::

1. **Удалённые скрипты появляются снова** — включите «синхронизацию удаления» на всех устройствах

## Проблемы с авторизацией Cookie

#### В: GM_cookie не получает cookies?

1. **Не появляется окно авторизации** — убедитесь, что `GM_cookie` объявлен в `@grant` скрипта, и через `@connect` указаны нужные домены

## Потеря данных скриптов

#### В: После открытия браузера все скрипты пропали?

1. **Задержка инициализации** — при старте браузера ScriptCat ещё может загружать данные. Подождите несколько секунд или перезапустите браузер
2. **«Чистильщики»** — 360 Security Guard, CCleaner и подобные могут удалять данные расширений. Исключите данные расширений браузера в настройках очистки
3. **Регулярные бэкапы** — используйте экспорт или [облачную синхронизацию](/docs/use/sync/) для резервного копирования скриптов и настроек
