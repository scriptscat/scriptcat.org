# 多语言（i18n）约定

> EN summary: the site ships 20 locales; `zh-Hans` is the unprefixed default. Never branch on hardcoded locale names — read `i18n.currentLocale` / `i18n.locales` from `useDocusaurusContext()`. Plain `<a href="/...">` needs `withBaseUrl()`; `<Link to>` does not. All UI copy goes through `<Translate>` / `translate()`, and every non-default `code.json` must preserve the English key set. Run `pnpm run typecheck && pnpm run build && pnpm run check` for all configured locales before opening a PR.

本文是 [AGENTS.md](../AGENTS.md) 「多语言」一节的展开；[CONTRIBUTING.md](../CONTRIBUTING.md) 管的是 markdown 文档的结构约定，本文管**代码和配置层面**的多语言约定。下面每一条都对应一个真实踩过的坑，改动 `src/`、`docusaurus.config.js` 或 `deploy/` 前请先扫一遍。

站点当前支持 20 个 locale，唯一来源是 `docusaurus.config.js` 的 `i18n.locales` / `localeConfigs`。不要在本文复制一份容易漂移的完整列表；主要来源关系如下：

| locale | URL 前缀 | 文档来源 |
|---|---|---|
| `zh-Hans`（默认） | 无（`/`） | `docs/` |
| `en` | `/en/` | `i18n/en/docusaurus-plugin-content-docs/current/` |
| `ru` | `/ru/` | 同上的 `i18n/ru/...`，缺失时按 `scripts/check-config.json` 回退到 `en` |
| `zh-Hant` | `/zh-Hant/` | 本地翻译；`change/` 按配置回退到 `zh-Hans` |
| 其他翻译 locale | `/<locale>/` | 本地翻译；`change/` 按配置回退到 `en` |

## 1. 不要假设只有两种语言

这是本仓库最容易犯、也最容易漏检的错。以下写法都出现过：

```tsx
const zh = i18n.currentLocale !== "en";                       // ru 被判成中文
const isEnglish = location.pathname.startsWith("/en/");        // /ru/ 被判成中文
window.location.href = "/en/" + pathname.replace(/^\//, "");   // /ru/x 拼成 /en/ru/x（404）
```

规则：

- 判断当前语言用 `useDocusaurusContext().i18n.currentLocale`，**不要解析 URL**。
- 表达"非默认语言"写 `currentLocale !== defaultLocale`，不要枚举语言名。
- 需要遍历语言时用 `i18n.locales`，标签和路径段取 `i18n.localeConfigs[locale]` 的 `.label` / `.path` / `.htmlLang`——这些都来自 `docusaurus.config.js`，以后加语言不用改代码。参考 `src/components/landing/LandingNav.tsx` 的 `LangSwitch`。
- 要给路径换 locale 前缀，**必须先剥掉当前路径上已有的前缀**再拼新的，否则会拼出 `/en/ru/...`。参考 `src/theme/Root/index.tsx` 的 `splitLocale()` / `localePrefix()`。

**这类假设不只藏在 `src/` 里**，还有两处按 locale 枚举、必须手工同步的地方：

| 位置 | 内容 | 漏改的后果 |
|---|---|---|
| `docusaurus.config.js` 的 `metadataByLocale` | 每个 locale 的 SEO `keywords` / `description` | 回落到默认 locale，新语言页面挂着中文 meta |
| `deploy/docker/nginx.conf` 的 `@handle_404` | 按 URL 前缀分流到各语言的 `404.html` | 该语言的 404 显示成中文页面（构建和 `check` 都发现不了，只有线上能看出来） |

## 2. 原生 `<a href="/...">` 必须手动补 baseUrl

非默认 locale 的 `siteConfig.baseUrl` 是 `/<locale>/`，不是 `/`。

| 写法 | 是否自动带 baseUrl |
|---|---|
| `<Link to="/docs/x">`（`@docusaurus/Link`） | ✅ 首选 |
| 原生 `<a href="/docs/x">` | ❌ |
| antd `<Button href="/docs/x">` | ❌ |
| markdown 里的 `[x](/docs/x)` | ✅（MDX 会渲染成 `Link`） |

原生标签一律套 `withBaseUrl()`：

```tsx
import { useBaseUrlUtils } from "@docusaurus/useBaseUrl";
const { withBaseUrl } = useBaseUrlUtils();
<a href={withBaseUrl("/docs/use/use/")}>…</a>
```

`withBaseUrl` 对带协议的外链原样返回，也不会重复添加已有前缀，所以可以无脑套。踩过的地方：`src/theme/Footer/index.tsx`（**每一页都在**，影响最大）、`LandingNav`、`shared.tsx` 的 `usePrimaryInstall`、`pages/uninstall.tsx`。

自查：`grep -rn 'href="/' src/ --include='*.tsx'` 应当只剩语言切换器里刻意写的站点根路径。

## 3. UI 文案一律走 `<Translate>` / `translate()`

- JSX 文本节点用 `<Translate id="...">中文默认值</Translate>`。
- 需要拼进字符串或属性时用 `translate({ id, message })`。
- 新 key 先加到英文规范源 `i18n/en/code.json`，再以相同位置加入所有其他非默认 locale；zh-Hans 允许使用 JSX 里的内联默认值和 Docusaurus 生成的默认语言键。
- **所有非默认 locale 的 `code.json` 必须与英文保持键集合一致**，由 `check:i18n-ui` 强制检查。新增 key 时仍应尽量放在与英文相同的位置，避免不必要地重排贡献者已有翻译。
- 装饰性的示例代码块里的文案（`// @name 视频倍速控制`、`GM_notification('签到成功')`）也要翻译，但注意版式，见第 5 条。
- 语言名本身不翻译：语言切换器里的"简体中文"在英文/俄文页面上仍是"简体中文"（并带 `lang="zh-Hans"`），这是惯例。

自查（应当只剩注释和语言名）：

```bash
grep -rnP '[\x{4e00}-\x{9fff}]' src/ --include='*.tsx'
```

## 4. 外链里不要写死语言路径段

`https://addons.mozilla.org/zh-CN/firefox/addon/scriptcat/` 会把英文/俄文用户送到中文商店页。去掉 `/zh-CN` 即可，商店会按浏览器语言自己跳。同理 Chrome / Edge 商店链接都不要带 `hl=` 之类的参数。

已知例外：`src/theme/Footer/index.tsx` 里的 `https://scriptcat.org/zh-CN/`——脚本站是另一个站点，其多语言路径规则未确认，暂时保留。

## 5. 译文长度会影响版式

落地页的示例代码卡片对行宽敏感：

- `.codeCard` 是**固定 360px** + `overflow: hidden`。
- 编辑器 mock 的行号是写死的 11 个 `<span>`（`Array.from({ length: 11 })`），任何一行折行，行号就和代码错位。

所以示例代码块里的译文，长度不要超过该代码块**原有最长行**。改完一定看构建产物，不要只看中文版。

## 6. 跨语言复用的锚点要写显式 heading id

Docusaurus 的锚点来自**渲染后的标题文本**，所以俄语标题会生成西里尔锚点，英文标题生成英文锚点，两者不通用。

当一个页面被多个 locale 共用时（例如非英文 changelog 复用中文或英文源，其中的链接指向目标文档锚点），就必须在**各语言**的目标标题上写显式 id：

```markdown
### Установка через загрузку распакованного расширения {#load-unpacked-extension-installation}
```

`onBrokenAnchors: "throw"` 会在构建时抓到不一致，但必须构建**全部配置 locale**才会暴露——所以别用 `--locale` 只构一个就下结论。

## 7. 图片二进制只存一份

见 [CONTRIBUTING.md](../CONTRIBUTING.md) 新增文档第 6 条：语言无关的截图统一引用中文或英文规范源；只有可见内容真正本地化时才保留 locale 专属图片。

## 单一来源回退（fallback）机制

`change/` 下的更新日志只维护中文和英文两套源，避免翻译漂移。`zh-Hant` 复用中文源，其他翻译 locale 复用英文源。实现方式：`docusaurus.config.js` 根据 `DOCUSAURUS_CURRENT_LOCALE` 和 `scripts/check-config.json` 选择 docs 插件的底层 `path`，locale 自己存在的文件仍会覆盖底层源。

**注意**：这个 trick 的作用范围是**整棵树**——locale 下缺任何一个文件都会静默回退到底层源，而不只是 `change/`。`scripts/check-config.json` 的 `paths` 只是给 `check:i18n` 用的白名单，Docusaurus 本身不认它。所以：

- 漏译不会让构建失败，只会悄悄显示英文 → **必须依赖 `pnpm run check`**。
- 新增有意的回退路径时，要同时改 `check-config.json` 和 `CONTRIBUTING.md`。
- `check:fallbacks` 会在 `build/` 产物里核对这些页面的 edit 链接确实指向英文源，防止哪天配置失效而没人发现。

## 新增一个 locale 的清单

以 `xx` 代指新语言。逐项走完，最后必须执行全部配置 locale 的全量构建。

1. `docusaurus.config.js`：`i18n.locales` 加 `"xx"`，`i18n.localeConfigs.xx` 填 `label` / `direction` / `htmlLang`；`metadataByLocale` 加一组本地化的 `keywords` / `description`。
2. `i18n/xx/code.json`：从 `i18n/en/code.json` 复制后逐条翻译，**保持键顺序一致**。
3. `i18n/xx/docusaurus-theme-classic/navbar.json` / `footer.json`：翻译 `message` 字段（key 和 `description` 里的中文是 `write-translations` 生成的，保持原样）。
4. `i18n/xx/docusaurus-plugin-content-docs/current.json`：翻译侧边栏分类名和 `version.label`。
5. `i18n/xx/docusaurus-plugin-content-docs/current/`：镜像需要翻译的文档；`change/` 等单一来源路径不要复制，在 `scripts/check-config.json` 的 `i18nDocFallbacks` 里声明。图片不要复制语言无关的二进制。
6. `scripts/url-inventory.txt`：用 `node scripts/check-url-inventory.mjs --write` 更新，新增路由数应当等于每个 locale 的页面数。
7. 检查代码里是否还有第 1、2 条描述的两语言假设——`Root` 的重定向和落地页语言切换器已经是配置驱动的，正常不需要改。
8. `deploy/docker/nginx.conf`：`@handle_404` 的正则里加 `xx`，并加一个 `location = /xx/404.html`。**这一步没有任何检查脚本能兜住**，漏了就是线上该语言的 404 页变中文。
9. **Algolia DocSearch 爬虫配置需要同步加上 `/xx/`**，见下节。
10. 检查 `CONTRIBUTING.md`、本文和 `agents/i18n-terminology.md` 是否需要同步新语言规则或术语。
11. `pnpm run typecheck && pnpm run build && pnpm run check`，然后打开 `build/`、`build/en/`、`build/xx/` 以及至少一个 RTL locale 抽查，确认 `<html lang>`、导航、页脚、语言切换器、图片、fallback 和 `404.html` 都对。

## SEO 与搜索

Docusaurus 自动处理的部分（不用手写）：`<html lang>`、`canonical`、`hreflang` 交叉引用（含 `x-default`）、`og:locale` / `og:locale:alternate`、`docsearch:language`、各 locale 独立的 `sitemap.xml`。

需要人工处理的：

- `metadataByLocale`（`docusaurus.config.js`）从各 locale `code.json` 的 `homepage.meta.keywords` / `homepage.meta.description` 生成；两项都必须本地化，缺失时配置应直接报错。
- **Algolia DocSearch 的爬虫配置在 Algolia 后台，不在本仓库**。新增 locale 后如果不同步更新爬虫，该语言页面上的搜索框会返回空结果——`contextualSearch: true` 会按 `docsearch:language` 过滤，索引里没有对应语言的记录就什么都搜不到。

## 已知例外与待办

- **Algolia 爬虫尚未收录 `/ru/`**：俄语页面的搜索目前是空的，需要在 Algolia 后台补爬虫配置。
- **本文的约定目前没有自动拦截**：`.gitea/workflows/ci.yaml` 会在每个 PR 上跑 `pnpm run typecheck && pnpm run build && pnpm run check`，所以文档配对、URL 契约、frontmatter、断链断锚点都是硬性把关的；但本文第 1～5 条（写死语言名、漏 `withBaseUrl`、硬编码中文、译文过宽）**没有对应的检查脚本**，只能靠 review 和自查命令。加检查脚本的话 CI 会自动生效。
- **`LINKS.search()` 的关键词有意保留中文**（`src/components/landing/shared.tsx`）：场景卡片的标题是翻译过的，但跳转到脚本站的搜索关键词仍是"去广告""购物"等中文。脚本站内容以中文为主，换成外语关键词很可能搜出 0 条结果，属于有意为之。若确认脚本站支持多语言搜索再改。
